# 右键菜单管理

点击侧边栏「右键菜单管理」打开管理页面。v0.7.0 重构了读取、命令身份和页面组织，研究依据见 [源码对照记录](menu-manager-redesign.md)。

## 查找菜单

v0.8.0 默认使用三层结构：**软件 → 菜单条目 → 出现位置**。

第一层显示软件名称和条目数量，例如 WPS Office、百度网盘；点击软件展开第二层的菜单条目，再点击条目展开第三层，显示文件、文件夹、桌面空白处、特定类型等注册位置与各自开关。第三层可单独调整一个位置，也可使用「全部可调整位置」开关；只读位置不参与批量调整。

只有命令身份一致的跨位置注册才合并；名称相同的不同命令分开。相同父命令在不同位置的子命令会合并位置；不同父菜单中的同名子命令分开。注册的子菜单条目归到父菜单所属软件，第二层用路径说明它原本属于哪个子菜单，不增加额外的嵌套层级。

搜索软件名会展开该软件的条目；搜索条目或出现位置会找出相关条目，第三层仍完整显示该条目的所有位置。「只看可调整」筛选有可调整位置的条目，条目中的只读位置仍保留说明。软件列表和较长的条目列表分别分页，避免一次展开大量内容。

「选择文件」「选择文件夹」根据具体对象的当前关联、SystemFileAssociations、PerceivedType 和通用注册来源筛选相关软件与条目，展开后仍显示条目的全部位置。这里是来源分析，不能完全复现资源管理器按文件内容、多选和软件设置生成的实时菜单。

「新建模板」「发送到」「打开方式」「归序停用」保留独立入口，同样逐层展开。新建模板和发送到按实际账户来源分组，不猜测为某个软件。技术注册路径和原始名称收在第三层的「来源与说明」中。

详情显示原始名称、注册来源、修改范围和只读原因，并可复制来源位置。可解析的私有子菜单、CommandStore 引用和 ExtendedSubCommandsKey 保留父子关系；组件运行时生成的子命令不主动展开。

## 名称和状态

优先读取注册中的本地化名称、资源字符串和应用包清单。v0.7.1 取消主动创建第三方 COM 菜单组件：即使只调用名称接口，组件初始化也可能启动所属程序或显示首次设置窗口（例如旧版 Windows Media Player）。独立进程与超时不能阻止这种副作用。

打开、刷新和分析菜单均不为识别名称启动所属软件。无法被动读取的名称保留软件名与原始标识，归序自己的复制路径命令使用已知名称；不再运行动态标题/子命令查询。旧的 `--menu-probe` 参数直接拒绝，不激活组件，也不当成归档文件参数处理。

「已注册 · 条件显示」表示组件已注册，其软件仍可能按所选对象决定是否显示。静态注册的「已启用」也不保证在所有场景显示。分类描述的是命令/组件机制，不根据传统注册表位置猜测其一定属于一级菜单或“显示更多选项”。

## 能调整哪些项目

| 项目 | 操作范围和方式 |
| --- | --- |
| 普通静态命令、私有父菜单 | 当前账户的 LegacyDisable 覆盖 |
| 私有子命令 | 当前账户的 HideBasedOnVelocityId DWORD 覆盖 |
| 传统扩展组件 | 当前账户、该注册位置的无效 CLSID 覆盖；组件可能生成多条菜单 |
| 打开方式 | 当前账户、Applications 或文件类型关联的 NoOpenWith 覆盖；不更改默认打开程序 |
| 新建模板 | 将该来源的 ShellNew 原子重命名为 TidyDrop.DisabledShellNew；保留全部值、类型和子项 |
| 发送到 | 给当前账户 SendTo 目录中的普通文件添加 Hidden 属性；保留入口文件与其目标 |

整机 HKLM 新建模板需要 Windows 管理员确认，影响全部账户。当前账户 HKCU 模板不需要管理员。两种来源各自列出；同一类型两处都有模板时，需要分别调整。归序不更改注册表所有权或权限。受权限保护的模板可能仍无法调整，软件会报告失败。

「打开方式」的应用列表与文件类型推荐分别注册，需要分别调整。隐藏应用列表项不能保证消除单独注册的类型推荐或系统最近使用记录。

新建模板覆盖常规文件类型的 ShellNew 注册；系统目录/快捷方式模板不提供开关。发送到中的目录、链接目录、超过 8 MB 的项目仅查看；文件名以入口名显示。

Windows 基础组件、已被其他工具隐藏的项目、无效残留注册、公共共享子命令、第三方 Win11 一级菜单组件和动态子命令仅查看。可在所属软件设置中调整一级菜单；归序不为了隐藏菜单卸载软件包，也不提供全局 CLSID 屏蔽开关。

页面顶部单独管理归序自己的一级「复制文件路径」命令：添加、移除、修复。文件夹内仍未显示时，修复后重开文件夹窗口；缓存仍未更新可退出并重新登录 Windows。

## 恢复记录

普通菜单继续使用 `HKCU/Software/TidyDrop/MenuOverrides`，保留 v0.6.3 的 ID 和已有恢复记录。写入前保存原值、原类型、注册指纹和已写值；恢复只撤回自己的覆盖。软件更新、其他工具更改或原注册消失时拒绝覆盖。

新建模板和发送到使用 `HKCU/Software/TidyDrop/SpecialMenuOverrides`：模板记录来源和注册树指纹；发送到记录内容/创建时间指纹和原属性。重命名是原子操作，不复制或删除模板树。中断后可依据已保存记录恢复；备份与原位置冲突、内容或属性变化时保留记录并报告失败。

管理员助手仅接受本账户、已枚举的整机新建模板 ID，重新核验状态，不接受任意注册路径；用另一个管理员账户提升时拒绝操作，以免恢复记录落到其他账户。部分项目失败不撤回已成功的项目，成功部分仍可恢复。

「归序停用」集中显示恢复记录；「恢复归序停用的项目」同时恢复普通菜单与特殊菜单。记录属于当前 Windows 账户，移动程序和重装后仍在。卸载不会自动撤销用户选择的菜单设置；卸载前可恢复，或重新安装后恢复。已删除的入口不会被重新创建。

操作后发送外壳刷新通知。资源管理器可能缓存扩展与新建列表；重新右键、重开窗口或退出并重新登录后查看。归序不会自动重启资源管理器。

## 验证范围

自动检查只修改随机生成的 HKCU 测试注册和临时文件，不调整真实第三方菜单。通过 Windows Shell 实际枚举验证普通静态命令、私有子命令和新建模板的出现、隐藏、恢复；检查恢复后原值类型、二进制数据、子项与快捷方式内容保留，以及其他工具/软件更新冲突保护。

界面检查覆盖三层展开、同名命令的独立身份、逐位置开关与批量恢复、搜索后保留全部位置，以及刷新后保留展开状态；名称检查验证未知组件的身份和状态保留，以及不激活测试组件。安装检查验证独立运行、升级和卸载保留用户数据。管理员助手的参数拒绝规则有自动检查；整机模板操作仍取决于 Windows 实际权限。

当前面向 Win11 x64 资源管理器，不管理其他账户的普通菜单、32 位外壳、Win+X 或 Internet Explorer 菜单。
