# 归序收纳功能：开源项目参考与后续计划

调研日期：2026-10-11。当前版本 v0.9.0。下面除「删除」外均为待评估功能，没有默认开启或实现。右键菜单管理本轮保持现状。

## 参考项目

| 项目 | 仓库中可确认的功能 | 对归序的启发 |
| --- | --- | --- |
| [organize](https://github.com/tfeldmann/organize) | 重复文件检测、文件/文件夹规则处理、冲突处理、模拟执行、EXIF 与文档文本提取 | 收纳前提醒重复；规则变化先展示实际影响；以后可按照片拍摄时间或文档内容辅助查找 |
| [TagSpaces](https://github.com/tagspaces/tagspaces) | 本地文件与文件夹管理、标签、按名称或标签搜索，标签可写入文件名或旁存元数据；媒体查看、缩略图服务 | 在日期和类型之外增加项目标签；元数据留在归序清单中，保持材料原名；提供轻量预览 |
| [FileOMate](https://github.com/rogers-cyber/FileOMate) | 监控指定目录、关键词到目标目录的规则、移动前预览、未匹配材料处理、操作统计 | 用户可以自选桌面或下载目录自动收纳；允许暂停，等下载完成再整理；提供简单规则而非编程配置 |

这里只借鉴产品设计。没有复制第三方项目的源码、图标或规则字典；引入代码或依赖时另外核对许可证。

## 按日常价值排序

### 1. 重复材料提醒

**建议优先级：高。** 同一份报告反复从聊天或邮箱下载，是日常最容易遇到的重复来源。

- 收纳前先按大小缩小候选范围，再用内容哈希确认；同名不等于同内容。
- 提醒「已经收过这份材料」，提供查看现有材料、仍然收纳、跳过三个选择。
- 默认不自动删除源文件，不自动合并内容不同的版本。
- 哈希可按需计算并缓存；历史已有的哈希只在确认材料没有被外部编辑时复用。
- 文件夹重复检测单独评估，第一版只检测文件。

### 2. 项目标签与简短备注

**建议优先级：高。** 用户通常记得材料属于哪个项目，未必记得收纳日期或文件类型。

- 例如「装修」「毕业论文」「报销」「客户 A」，一份材料可以有多个标签。
- 标签与备注存入材料清单，不改文件名、不搬动已有材料。
- 日期、类型和标签共同筛选；项目入口跨日期、跨类型查看同一批材料。
- 清单格式需要版本迁移，刷新目录时保留已有标签，删除与恢复后的标签保留策略需明确。

### 3. 轻量预览

**建议优先级：中高。** 先确认是哪份材料，再用外部软件打开。

- 先做图片缩略图、纯文本预览、文件大小与修改时间；PDF 预览随后评估。
- 只为当前可见材料加载，缩略图缓存与清单分开，不能启动时读取所有文件内容。
- 文件夹先显示内部数量或少量内容，不把内部文件展开成新的独立收纳项目。

### 4. 可选的目录自动收纳

**建议优先级：中。** 保留现在的拖入入口，另外允许用户选择下载目录或桌面目录。

- 默认关闭，明确显示正在监控哪个目录，随时暂停。
- 等文件大小和修改时间稳定后再处理，忽略临时下载文件、快捷方式及用户指定项目。
- 重复事件去重；不能监控归档空间自身，避免循环收纳。
- 失败材料保留原位，操作记录能追溯。第一次开启先展示预计收纳范围。

### 5. 简单的分类规则

**建议优先级：中。** 例如把某些扩展名加入「文档」，或将文件名含「发票」的材料加上「报销」标签。

- 先支持扩展名、文件名关键词；提供可视化规则，不要求用户写脚本。
- 多条规则命中时有明确顺序；对已收纳材料重新分类前先预览。
- 默认继续使用归序管理的统一目录，不给每条规则引入任意外部目标路径。

## 本轮已补齐：删除

- 日期与类型视图均提供单份删除，支持勾选并批量删除当前筛选结果。
- 确认窗口展示材料名称、数量；有文件夹时明确提示内部内容一起处理。取消和 Esc 不执行操作。
- 使用 Windows 回收站，拒绝永久删除；不能回收时保留材料并报告原因。
- 仅按当前归档位置的清单身份查找目标，不接受前端传入任意文件路径。拒绝目录链接、云端占位项及不能确认的管理目录。
- 清单在原有互斥锁内增量更新；记录保留原始收纳信息，成功时标记「已移入回收站」。失败项目保留，批次可部分成功。
- 恢复方式：在 Windows 回收站还原，再点归序「刷新」。这与整理记录中的「撤销收纳」不同，归序暂不提供自己的回收站或一键还原。
- 已验证生成的文件与整包文件夹实际回收、还原后字节和空目录不变，以及取消、批量操作、清单保存失败和中断恢复。

## 暂缓

AI 自动分类、云同步、复杂脚本规则、自动永久清理暂缓。当前以收纳、找回材料和安全删除的完整日常流程为主。大列表性能方案仍见 [后续开发记录](development-notes.md)，本轮没有进行全量渲染优化。
