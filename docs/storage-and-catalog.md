# 存储目录与材料清单

对应版本：v0.5.0。记录日期：2026-10-11。

## 两份信息各自负责什么

实际材料保存在归档总文件夹下，按收纳日期和类型组织。持久化清单记录这些材料的位置和分类，供归档空间读取。程序旁的 `data/history.json` 继续记录原位置、移动状态和校验值，用于撤销与中断恢复。

```text
归档总文件夹/
└─ 归序/
   ├─ .tidydrop/
   │  └─ catalog.json
   └─ 2026-10/
      └─ 2026-10-11/
         ├─ 文档/会议纪要.docx
         └─ 文件夹/项目材料/（内部保持原样）
```

`.tidydrop` 是管理目录，不作为材料显示。正常情况下只有清单文件；操作期间会有 `pending` 标记，损坏的清单修复时会留下 `catalog.invalid-*.json` 备份。

## 清单格式

```json
{
  "version": 1,
  "updatedAt": "2026-10-11T12:00:00+08:00",
  "items": [
    {
      "id": "示例项目ID",
      "relativePath": "归序\\2026-10\\2026-10-11\\文档\\会议纪要.docx",
      "category": "文档",
      "date": "2026-10-11",
      "isDirectory": false
    }
  ]
}
```

路径相对于用户选择的归档总文件夹，文件名由路径得出。读取时将相对路径与当前总文件夹组合，因此整个归档目录迁移后仍可读取清单。加载时校验格式、日期、重复路径和路径范围，不逐个检查材料是否存在。

历史记录仍使用绝对路径，迁移目录不会自动改写旧的撤销记录；清单可迁移不等于旧记录的撤销位置会自动迁移。

## 正常读取和更新

| 操作 | 行为 | 是否扫描材料目录 |
| --- | --- | --- |
| 正常打开软件 | 读取 `catalog.json`，生成运行中的材料列表 | 否 |
| 切换日期或类型、搜索 | 筛选已加载的列表 | 否 |
| 拖入材料，包括关闭软件时拖入桌面入口 | 收纳后更新本批受影响的条目并保存清单 | 否，首次建立或修复除外 |
| 撤销 | 恢复材料后移除清单条目；失败时按实际位置保留条目 | 否，首次建立或修复除外 |
| 点击「刷新」 | 遍历实际目录，核对并重建清单 | 是 |
| 清单缺失、损坏，或存在中断标记 | 从目录和兼容的旧历史记录恢复清单 | 是 |

正常收纳和撤销只检查本次操作涉及的位置。更新条目后，整个 JSON 文件通过临时文件、写入刷新和原子替换保存；当前没有采用数据库或只追加日志的索引格式。

## 首次迁移与手动核对

已有归档首次使用 v0.5.0 时，扫描一次原有材料并保存清单。按路径去重，保留归档目录中的材料和历史记录能识别的旧版材料，不搬动它们。

手动核对逐层遍历 `归序/月份/有效日期/分类/材料`。分类文件夹里的文件夹整体记为一个项目，不拆分内部文件；管理目录、链接或云端占位项、`.tidydrop-` 临时副本不作为普通材料加入。

按类型查看跨日期材料，是从清单中筛出该类型的全部条目。日期筛选为「全部日期」时跨日期汇总；选中某一天时保留日期限制。

软件外添加、移动或删除材料不会自动改变清单。需要时点击「刷新」。如果清单里的材料已被移走，「打开位置」会提示更新。

## 操作中断与保存失败

每批实际移动前，归序先读取或建立清单，再持久化 `pending` 标记。原有整理记录仍在移动前保存操作意图和校验信息。

批次完成后，按受影响项目的实际目标位置更新清单，保存成功后移除标记。这样覆盖了材料已移动、清单尚未保存期间的中断：下次读取发现标记，会核对实际目录并重新保存清单。

- 清单准备失败时，收纳停止，源材料保持原位。
- 文件已经成功收纳或恢复、清单提交失败时，保留已完成的移动和中断标记，并报告清单待修复。
- 清单内容损坏或路径校验失败时，先备份元数据，再扫描恢复。
- 手动核对失败时不替换之前保存的清单。当前窗口保留同一归档位置上已加载的列表，并提示错误。
- 按归档总文件夹建立命名互斥锁，将多个归序实例对同一清单的读取和修改串行化，避免覆盖彼此的新增条目。

清单恢复只修复元数据，不删除或重排材料。核对目录不等于重新验证所有文件内容；内容校验继续由收纳与撤销逻辑负责。
