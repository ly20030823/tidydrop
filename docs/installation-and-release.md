# 安装与 GitHub Release

从 v0.6.1 起提供 Windows 11 x64 安装程序，文件名为 `TidyDrop-Setup-0.6.1-win-x64.exe`。下载入口：[GitHub Releases](https://github.com/ly20030823/tidydrop/releases)。

## 另一台电脑怎么使用

1. 下载 Release 附件中的 `TidyDrop-Setup-版本-win-x64.exe`，双击运行。
2. 默认安装到当前账户的 `%LOCALAPPDATA%\Programs\TidyDrop`，可更改到其他可写位置。安装程序自带 .NET 9 x64 运行环境，不需要单独安装 .NET。
3. 保留「创建桌面入口」。需要复制路径功能时，勾选「添加一级右键菜单」，阅读签名说明，完成管理员确认；不勾选也能正常使用归序。
4. 首次打开归序，选择这台电脑的归档总文件夹。以后把文件或文件夹拖到桌面「归序」图标即可收纳。

软件界面需要 WebView2。安装程序先检查系统；已有时不重复安装，缺少时使用随附的微软安装器联网下载安装。没有网络且缺少 WebView2 时，安装会明确停止，联网后重试即可。

当前仍是个人开发签名，Windows SmartScreen 可能显示「无法识别的应用」。请核对文件来自本仓库的 Release，必要时通过「更多信息」查看并选择是否继续；本地签名不会自动获得微软的应用信誉。请勿关闭系统安全检查来安装。

## 右键菜单与证书

一级菜单使用原生 `IExplorerCommand` 和带外部路径的已签名 MSIX 身份包。自签名包需要证书位于 **LocalMachine / TrustedPeople（本机 / 受信任人）**；v0.6.0 使用 CurrentUser 的做法在实际部署中报 `0x800B0109`，v0.6.1 已修正。

证书信任对电脑上所有账户生效，也适用于同一私钥签名的其他包。只导入公开代码签名证书，不导入私钥，不加入根证书库。菜单注册则在当前账户执行：即使输入的是另一个管理员账户的凭据，也只让管理员辅助步骤处理本机信任，避免把菜单误装到管理员账户。

拒绝管理员确认时不会建立新的信任，菜单不会添加；归序主体已安装，收纳功能仍能使用。之后可在「归档设置」中添加。若信任步骤成功但包注册被系统阻止，证书信任可能暂时保留以便重试；从该程序卸载或在设置中移除菜单时会清理。

移除或卸载只清理由归序新增并记录的证书，已有的同证书信任保留。其他账户仍注册着此发布者的菜单时，保留信任供其使用；最后一个账户移除时才清理。清理需要管理员确认，取消会暂停卸载，以免留下无法清理的菜单组件。

详细说明见 [右键菜单说明](context-menu.md)。

## 升级、卸载和便携版迁移

同一安装目录运行新版安装程序即可升级，保留 `data` 中的设置、整理记录和界面缓存。已有的菜单随安装更新绑定。安装程序不会强制结束正在收纳材料的归序；遇到占用时请等待收纳完成并关闭软件后重试。

卸载在删除程序前取消本安装目录的菜单注册并清理信任，不影响绑定到另一处归序的菜单。卸载保留自行生成的 `data` 和所有归档材料。重新安装到同一目录即可继续读取保留的设置、记录。

安装版和旧便携版放在不同目录时，各自读取自己目录的 `data`。需要迁移时，先关闭两处归序，备份旧版 `data`，再把旧版的 `data` 复制到安装目录；不要覆盖另一处已有的重要记录。保留原归档位置即可继续使用现有清单。换电脑时也要复制实际材料并选择新电脑的归档位置，安装程序不会跨电脑同步材料或撤销记录。

## 开发构建与发布

需要 .NET 9 SDK、Node/pnpm、Visual Studio C++ 桌面工具、Windows SDK 和 Inno Setup 6.5–6.7（当前验证为 6.7.3，7.x 的脚本 API 不兼容）。安装向导的简体中文翻译来自 kira-96 的 MIT 项目，许可随程序附带。

```powershell
./scripts/build-installer.ps1 -InnoCompiler 'C:\Program Files (x86)\Inno Setup 6\ISCC.exe'
```

构建先运行核心与原生命令检查，生成自带运行环境的 win-x64 程序，再构建安装程序、添加本地签名并生成 SHA-256 校验文件。默认包含 .NET 9.0.20，升级运行环境版本时在 `scripts/build.ps1` 中更新并重新验证。

GitHub Release 应上传安装程序及对应 `.sha256`。可额外提供自带运行环境的便携 ZIP。禁止打包真实 `data`、检查产物、PFX/P12 或私钥。构建签名私钥始终留在本机构建者的证书库，不能导出。

CI 的临时开发签名仅用于构建验证；不自动发布为正式 Release，避免每次 CI 换证书造成重复信任。当前 Release 在维护者机器上使用同一非导出签名密钥构建和发布。以后换签名服务时调整发布者与迁移流程。
